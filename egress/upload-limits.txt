# egress/upload-limits.txt
# How much a container may send one host through its proxy in an hour before
# bxn warns (and, with `bxn egress upload-cap <container> on` under enforce,
# cuts it). This is an alarm for bulk uploads, such as a whole repository or
# a database dump, not a guard against leaks: a small secret passes any limit.
#
# These numbers are starting guesses, to be tuned from real use; see
# `bxn egress log <container> --uploads`. They're high on purpose, so normal
# work never sets them off.
#
# One entry per line: a hostname, or a wildcard "*.<domain>" (subdomains only,
# as in the allowlist), or "default", then a size: bytes, or a number with K,
# M, G or T (powers of 1024), or off. "#" starts a comment. A host's own entry
# wins over a wildcard, and the longest wildcard over a shorter one.
#
# Unlike egress/baseline.txt, bxn reads this file directly, with no approval
# step: a change here applies the next time bxn applies a container's policy
# (`bxn egress ls` notes the change; `bxn egress refresh` applies it). Your
# own limits go in ~/.config/boxen/egress-upload-limits.txt, in the same
# format, and a container's in `bxn egress upload-limit <container> <host>
# <size>`; for a host both name, the container's wins, then yours, then this
# file's.

default 250M
